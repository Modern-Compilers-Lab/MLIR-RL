`scf.forall`

Tiling is applied by either specifying `num_threads` or `tile_size`. If
`num_threads` is specified, then the tile size for each dimension `i` is
calculated dynamically via `ceilDiv(dimSize[i], num_threads[i])`.
`num_threads` and `tile_size` can be either static index attributes or
operation handles (or a mix thereof). Operation handles must be mapped to
exactly one op that has exactly one result of index type.

## Answer

1. **`transform.structured.tile_using_for`** generates a sequential loop nest (`scf.for`):
   - Use when you want scalar sequential tiling of a linalg op.
   - Returns handles to the tiled op and all generated loops.

2. **`transform.structured.tile_using_forall`** generates a parallel loop nest (`scf.forall`):
   - Use when tiling is parallelizable across dimensions.
   - Specify either `num_threads` or `tile_sizes`; exactly one must be provided.
   - Returns handles to the tiled op and the generated `scf.forall` op.

3. **Key operand:** `target` is a transform handle to the linalg op you wish to tile.

4. **Static vs. dynamic sizes:**
   - Static tile sizes go in the attribute (`static_sizes` or `static_tile_sizes`).
   - Use `ShapedType::kDynamic` (e.g., `-9223372036854775808`) in static attributes when a size is computed at runtime.
   - Provide corresponding operands in `dynamic_sizes` or `tile_sizes` handles for each dynamic entry.

5. **A static size of `0`** means "do not tile this dimension"—no loop is generated.

6. **`interchange` attribute** (optional, `tile_using_for` only): permutes the generated loops as a dense i64 array.

## Constraints / Preconditions

- **Target must be a linalg op** (or any op implementing `TilingInterface` for `tile_using_forall`). Non-conforming ops produce a silenceable failure.
- **Dynamic sizes must align:** If you provide `dynamic_sizes` handles, their list length must equal the number of `ShapedType::kDynamic` entries in `static_sizes`.
- **A `0` tile size generates no loop** for that dimension; if all are `0`, the transform is a no-op.
- **`tile_using_forall` requires `num_threads` OR `tile_sizes`**, not both; if `num_threads` is provided, compute ceilDiv internally.
- **Interchange (optional):** Only available for `tile_using_for`; permutes the order of generated loops.
- **Failure modes:** Definite failure if the internal tiling implementation for any op fails; silenceable failure if ops do not support the required interface.
