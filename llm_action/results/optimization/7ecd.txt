### `transform.loop.forall_to_parallel`
Converts `scf.forall` into `scf.parallel`. The operand handle must be associated with exactly one `scf.forall` payload operation. **Loops with outputs are not supported.** Returns a handle to the new `scf.parallel` operation.

### `transform.loop.forall_to_for`
Converts `scf.forall` into a nest of `scf.for` operations. Each new operation corresponds to one induction variable of the original multifor loop. The operand handle must be associated with exactly one `scf.forall` payload operation. **Loops with shared outputs are currently not supported.** Returns as many handles as the `forall` op has induction variables (one per generated loop).

### `transform.loop.parallel_for_to_nested_fors`
Converts `scf.parallel` into a nest of `scf.for` operations. Each new operation corresponds to one dimension of the original parallel loop. The operand handle must be associated with exactly one `scf.parallel` payload operation. **Loops with shared outputs are currently not supported.** Returns as many handles as the `parallel` op has dimensions.

---

## Answer

**To parallelize a loop or convert between loop types:**

1. **`scf.forall` → `scf.parallel`**: Use `transform.loop.forall_to_parallel` (does NOT support loops with outputs).
2. **`scf.forall` → nested `scf.for`**: Use `transform.loop.forall_to_for` (does NOT support loops with shared outputs).
3. **`scf.parallel` → nested `scf.for`**: Use `transform.loop.parallel_for_to_nested_fors` (does NOT support loops with shared outputs).
4. **Direct `scf.for` → `scf.parallel` conversion**: Not directly available in Transform dialect—you would need to first tile or restructure into `scf.forall` or `scf.parallel` via `transform.structured.tile_using_forall`.
5. Each operation consumes the input handle and returns a handle (or handles for the nested loop case).
6. All three operations require exactly one payload operation matched by the input handle.

## Retrieved Documentation (verbatim)

**`transform.structured.promote`** promotes the specified operands of a target linalg op into a separate memory buffer.

Key points:
- **Purpose**: Allocates temporary buffers for specified operands and inserts copy-in/copy-out operations.
- **Target**: A single linalg op satisfying `promoteSubviewsPrecondition` (must be compatible with promotion).
- **Return**: The modified target operation (in-place transformation).
- **Traits**: Functional style, reports tracking listener failures, applies to each op.

---

## Answer

1. **Use `transform.structured.promote`** — the primary Transform dialect operation for memory promotion.

2. **Key attributes to control promotion**:
   - `operands_to_promote`: array of operand indices to promote (e.g., `[0, 1]` to promote first two operands).
   - `use_alloca`: unit flag; if set, allocate via `alloca` (local/stack memory) rather than `alloc`.
   - `use_full_tile_buffers`: array of booleans; one per operand, controls whether to allocate full-tile or exact-size buffers.
   - `memory_space`: optional attribute specifying target memory space (e.g., shared memory for GPUs).
   - `alignment`: optional integer attribute for buffer alignment.

3. **Typical workflow**:
   - First tile the linalg op using `transform.structured.tile_using_for` or `transform.structured.tile_using_forall`.
   - Then apply `transform.structured.promote` on the resulting tiled operation to hoist operands into local/faster memory.

4. **Precondition**: The target operation must satisfy `promoteSubviewsPrecondition` (roughly: the op must be a structured linalg op with compatible access patterns; tiled ops typically qualify).

5. **Return handle**: Points to the same target operation, modified in-place with promotion logic inserted.

### `transform.gpu.map_nested_forall_to_threads`
