**`transform.loop.unroll`** (from Loop (SCF) Transform Operations)

Unrolls the given loop with the given unroll factor. The operation works on `scf.for` and `affine.for` loops, unrolling each to have up to the given number of loop body copies per iteration. If the unroll factor is larger than the loop trip count, the trip count is used instead.

**Operands:**
- `target`: TransformHandleTypeInterface instance (the loop(s) to unroll)

**Attributes:**
- `factor`: 64-bit signless integer attribute (positive value required)

**Return modes:**
- Does NOT return handles (the operation may result in the loop being removed after full unrolling)
- Ignores non-`scf.for` and non-`affine.for` ops and drops them from the result
- Succeeds if all target operations unroll properly; silenceable failure otherwise

---

## Answer

1. **Identify the loop(s)** to unroll by matching them via a handle (typically via `transform.structured.match` or other handle-producing ops).
2. **Apply `transform.loop.unroll`** with the matched loop handle and a positive `factor` attribute specifying the unroll count.
3. **Note:** The operation does **not** return a handle; if full unrolling occurs, the loop is removed entirely.
4. Works only on **`scf.for`** and **`affine.for`** loops; other loop types are silently dropped.
5. If `factor` exceeds the loop trip count, the trip count becomes the effective unroll factor.

## Answer

**Important note**: The Transform dialect provides conversions *away* from `scf.forall` and `scf.parallel`, not *toward* them. To parallelize loops, you typically:

1. **To create parallelism at the structured (linalg) level**: Use `transform.structured.tile_using_forall` (tiles a linalg operation into an `scf.forall`).

2. **To convert `scf.forall` → `scf.parallel`**: Use `transform.loop.forall_to_parallel` — converts forall to parallel form (handles single handles, no outputs).

3. **To convert `scf.forall` → nested `scf.for`**: Use `transform.loop.forall_to_for` — serializes forall into a nest of `scf.for` loops.

4. **To convert `scf.parallel` → nested `scf.for`**: Use `transform.loop.parallel_for_to_nested_fors` — serializes parallel into sequential `scf.for` loops.

For actual parallelization of unstructured `scf.for` loops, **no direct MLIR Transform operation exists in the index**. The recommended path is through structured operations (linalg tiling with forall).
