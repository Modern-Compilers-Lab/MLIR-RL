### 1. `transform.structured.interchange`

Interchanges the iterators of linalg operations using the `iterator_interchange` attribute. This operation applies loop interchange directly to `linalg::Generic` ops and similar structured operations.

**Key attributes:**
- `iterator_interchange`: A dense i64 array attribute specifying the permutation of iterator positions (must be non-negative values).

**Return modes:**
- Ignores non-linalg ops and drops them.
- Fails if the interchange attribute is invalid.
- Returns a handle to successfully interchanged operations only.

### 2. `transform.loop.coalesce`

Coalesces perfect loop nests by merging multiple nested loops into fewer loops (bottom-up, one-by-one manner). While not a direct interchange, it reorders/simplifies loop structure.

---

## Answer

- **Primary operation for loop interchange**: Use `transform.structured.interchange` with the `iterator_interchange` attribute to permute loop orders in linalg operations.
- **Attribute specification**: The `iterator_interchange` attribute is a dense i64 array defining a permutation. For example, `[1, 0]` swaps the first two loop dimensions.
- **Applicability**: Works on linalg::Generic and compatible structured ops; non-linalg ops are silently ignored.
- **Complementary operation**: Use `transform.loop.coalesce` if you need to merge adjacent loop nests after interchange or other transformations.
- **Handle requirements**: Both ops consume and return `TransformHandleTypeInterface` instances; the result handle points only to successfully transformed ops.
- **Failure handling**: If interchange fails on any op, the transform produces a definite failure; partial success is reflected in the returned handle subset.

## Answer

**`transform.structured.interchange` works ONLY on `linalg.generic` operations**, not on named ops like `linalg.matmul` or `linalg.conv_2d`.

From the retrieved documentation:
> "This operation **ignores non-linalg::Generic ops** and drops them in the return."

**To interchange loops on named linalg operations, you must first generalize them:**

1. **Generalize the named operation** to `linalg.generic` using `transform.structured.generalize`.
2. **Then apply `transform.structured.interchange`** on the resulting `linalg.generic`.

---

## Minimal Transform IR Skeleton

```mlir
module attributes { transform.with_named_sequence } {
  transform.named_sequence @__transform_main(%arg0: !transform.any_op {transform.readonly}) {
    // Match the named linalg op (e.g., linalg.matmul with tag)
    %matched = transform.structured.match attributes { tag = "operation_0" } in %arg0 
      : (!transform.any_op) -> !transform.any_op
    
    // Generalize to linalg.generic
    %generalized = transform.structured.generalize %matched 
      : (!transform.any_op) -> !transform.any_op
    
    // Now interchange on the generic form
    %interchanged = transform.structured.interchange %generalized 
      iterator_interchange = [1, 0, 2]  // Swap first two iterator dimensions
      : (!transform.any_op) -> !transform.any_op
    
    transform.yield
  }
}
```

---

## Constraints / Preconditions

- **Input ops must be generalized to `linalg.generic` first.** Named ops like `linalg.matmul`, `linalg.conv_2d` are silently dropped (no error, just ignored).
- **`iterator_interchange` attribute:** dense i64 array specifying the permutation. Must be valid and non-negative.
- If any interchange fails, the entire operation produces **definite failure**.
- The returned handle points only to successfully interchanged ops (may be empty).
