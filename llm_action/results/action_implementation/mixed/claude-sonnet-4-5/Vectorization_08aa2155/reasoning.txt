## Key Constraints & Requirements

1. **Tag-based targeting**: Must match `tag = "operation_0"` exclusively
2. **Hardware constraints**: AVX2 available (no AVX-512)
   - f64: realistic widths 2, 4, 8, 16 (prefer 2-8 for AVX2)

3. **Vector safety contract**: 
   - f64: N ≤ 16
   - Prefer rank-1 vectors
   - No tile-as-vector lowering
4. **Reusability**: Must work on matmul, conv, generic, and their transformed variants

### 1. **transform.structured.vectorize** (Primary vectorization operation)

Vectorize the target ops, which must be Linalg ops. Use optional vector sizes to specify exactly what configuration the vectorizer should use:
- **Without vector sizes**: "regular vectorization" — vector sizes are inferred from the target Linalg ops.
- **With vector sizes** (e.g., `vector_sizes [1, 4]`): "masked vectorization" — enforces the specified configuration.

**Key attributes:**
- `static_vector_sizes`: i64 dense array attribute
- `scalable_sizes`: i1 dense array attribute (for scalable vectors)
- `vectorize_nd_extract`: unit attribute (enable n-d extract vectorization)
- `assume_dynamic_dims_match_vec_sizes`: unit attribute
- `create_named_contraction`: unit attribute (create named vector contractions)

**Operands:**
- `target`: TransformHandleTypeInterface (the Linalg op to vectorize)
- `vector_sizes`: variadic of transform param or handle type (optional SSA values)

**Return behavior:** Produces a silenceable failure if any target op is not a Linalg op or fails to vectorize.

---

### 2. **transform.structured.vectorize_children_and_apply_patterns**

Vectorizes all children contained in the given `target` and applies supporting rewrite patterns. This is a bulk vectorization operation that only works on ops with the "isolated from above" property.

**Key attributes:**
- `fold_type_extensions_into_contract`: fold type extension ops into `vector.contract`
- `vectorize_padding`: activate vectorization of `tensor.pad` ops
- `vectorize_nd_extract`: enable n-d extract vectorization
- `flatten_1d_depthwise_conv`: unit attribute
- `disable_multi_reduction_to_contract_patterns`: deactivate multi-reduction to contract rewrite
- `disable_transfer_permutation_map_lowering_patterns`: deactivate explicit transpose lowering

**Operands:**
- `target`: TransformHandleTypeInterface

**Results:**
- `transformed`: handle to the target op

---

### 3. **transform.apply_patterns.vector.lower_contraction**

Indicates that vector contraction-like operations should be lowered to finer-grained vector primitives. Typically run after bufferization as part of lowering to LLVM or NVVM.

**Attributes:**
- `lowering_strategy`: `VectorContractLoweringAttr` — controls how `vector.contract` operations are lowered.

---

### 4. **transform.apply_patterns.linalg.pad_vectorization**

Apply patterns that vectorize `tensor.pad` operations using `vector.transfer_read` and `vector.transfer_write` operations.

## Answer

**Two main approaches to vectorize Linalg operations:**

1. **Targeted vectorization** — Use `transform.structured.vectorize` on individual Linalg ops:
   - Accepts optional `vector_sizes` attribute for masked vectorization (enforces specific vector widths).
   - Without `vector_sizes`, performs regular vectorization with inferred sizes.
   - Best applied **after tiling** to appropriate sizes.

2. **Bulk vectorization** — Use `transform.structured.vectorize_children_and_apply_patterns` for vectorizing all children in a container op:
   - Applies supporting patterns automatically (e.g., contraction creation, padding).
   - Requires target to be "isolated from above".
   - Fine-tune behavior via unit attributes like `vectorize_padding`, `fold_type_extensions_into_contract`.

3. **Post-vectorization cleanup** — After vectorization, optionally apply:
   - `transform.apply_patterns.vector.lower_contraction` to lower `vector.contract` to primitives.
   - `transform.apply_patterns.linalg.pad_vectorization` to vectorize `tensor.pad` ops.

## Answer

1. **Yes, `vector_sizes` can constrain vectorization to smaller widths.** When you specify `vector_sizes`, the operation performs "masked vectorization" with exactly those dimensions, rather than inferring sizes automatically.

2. **The `vector_sizes` attribute specifies static vector dimensions** as a list of positive integers (e.g., `[1, 4]`). Each value corresponds to a vectorization dimension.

3. **The constraint is that vector sizes must be ≥ iteration space sizes.** You cannot use a smaller vector size than the corresponding loop/dimension in the target Linalg op.

4. **Vector sizes can be static or dynamic (SSA values).** If dynamic, the handle must map to exactly one payload op with exactly one index-typed result.

5. **Masked vectorization is typical after tiling.** Use `transform.structured.vectorize` after tiling your ops to appropriate sizes; then specify vector_sizes to enforce specific vector widths.

6. **Key attributes for configuration:**
   - `static_vector_sizes`: DenseI64ArrayAttr with the sizes (e.g., `dense<[1, 4]>`)

## Retrieved Documentation

### **transform.structured.vectorize**
Vectorize the target ops, which must be Linalg ops. Supports two modes:
- **Regular vectorization**: vector sizes are inferred from the target Op (no vector_sizes argument).
- **Masked vectorization**: specify exact vector sizes via `vector_sizes [size1, size2, ...]` to enforce a configuration with masked vectors.

**Key constraint**: "Typically this operator should be applied to linalg operations that have **already been tiled to the appropriate sizes**."

Supports attributes like `vectorize_nd_extract`, `assume_dynamic_dims_match_vec_sizes`, `create_named_contraction`, and scalable vector sizes.

### **transform.structured.vectorize_children_and_apply_patterns**
Vectorizes all children (structured ops on shaped types) contained in a target with "isolated from above" property. Applies a set of rewrite patterns to enable vectorization and clean up results.

Supports fine-grained attributes:
- `vectorize_padding`: activates vectorization of `tensor.pad` ops (default: off).
- `fold_type_extensions_into_contract`: enables mixed-precision `vector.contract` creation.
- Other pattern controls (multi_reduction, transfer permutation maps).

**Important**: This transformation invalidates handles to payload ops contained inside the vectorization target.

### **transform.structured.tile_using_for**
Tiles a Linalg op with specified sizes, generating a loop nest with the tiled operation in its body. 
- Tile size `0` means "do not tile this dimension".
- Returns handles to the **tiled op** and the **generated loops**.

### **transform.structured.pad**
Pads operations before vectorization (e.g., to multiples of vector widths). Returns handles to padded op, padding op, and copy-back op.

### **transform.apply_patterns.linalg.pad_vectorization**
Pattern descriptor that vectorizes `tensor.pad` ops using `vector.transfer_read`/`vector.transfer_write`. Folding happens either with existing transfer ops or via rewrite with consumers.

## Answer

**To vectorize linalg operations effectively, follow this pattern:**

1. **Tile first (typically required)**: Apply `transform.structured.tile_using_for` with appropriate tile sizes to match your target vector widths and hardware cache/register constraints. The documentation explicitly states vectorization "should be applied to linalg operations that have already been tiled."

2. **Optional padding before tiling**: Use `transform.structured.pad` (with `pad_to_multiple_of`) to ensure iteration spaces are multiples of vector sizes, avoiding masked vectorization overhead.

3. **Vectorize the tiled op**: Use `transform.structured.vectorize` on the tiled operation with either:
   - **No vector_sizes** (regular vectorization): infer sizes from the tiled iteration space.
   - **Explicit vector_sizes** (masked vectorization): enforce specific vector configurations with masking.

4. **Alternative: Child vectorization + patterns**: For ops with children, use `transform.structured.vectorize_children_and_apply_patterns` with attributes like `vectorize_padding` to avoid separate pattern application steps.

5. **Handle padding ops**: If padding is present, optionally apply `transform.apply_patterns.linalg.pad_vectorization` to vectorize `tensor.pad` via transfer ops.

6. **Cleanup patterns**: The `vectorize_children_and_apply_patterns` variant automatically applies cleanup (contraction folding, transpose lowering, etc.); for standalone `vectorize`, you may need additional pattern passes.

## Constraints / Preconditions

- **Tiling is prerequisite**: Vectorization works best on already-tiled operations; iteration spaces must be suitable for vector widths (typically 4–8 for FP64, 8–16 for FP32 on AVX2).
- **Iteration space alignment**: If iteration space sizes are not multiples of vector size, masked vectorization will be triggered; consider padding beforehand with `transform.structured.pad`.
- **Handle validity**: After `vectorize_children_and_apply_patterns`, handles to contained ops are **invalidated**; do not reuse them downstream.
- **Linalg ops only**: Both `tile_using_for` and `vectorize` require Linalg ops; other ops are silently dropped or produce failures.
- **Vector size constraints**: For masked vectorization, specified vector sizes must be ≥ the iteration space sizes in each dimension.
