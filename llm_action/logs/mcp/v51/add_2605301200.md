## Phase 4: Best Schedule Shapes per Subset

### Summary by Kernel Subset

| Subset | Best Shape | Best Time | vs PyTorch | Key Driver |
|--------|-----------|-----------|------------|------------|
| Small | ParTile → VecSeq | 0.369 ms | 0.30x | Coarse parallel + light vectorization |
| Medium | ParThreads → VecPar | 37.92 ms | 1.47x | Max thread parallelism + vectorization |
| Medium | ParTile → VecPar | 39.07 ms | 1.42x | Tile-based parallelism + vectorization |
| Large | VecPar (alone) | 76.53 ms | 1.30x | Massive implicit parallelism |

### Cross-Kernel Insights
1. **Kernel size determines optimal strategy**: Small kernels need minimal overhead (ParTile → VecSeq), medium kernels benefit from parallelization + vectorization, large kernels with constrained dims benefit from VecPar alone.
2. **VecPar is universally competitive**: It never catastrophically fails and provides 1.2-1.5x vs PyTorch on medium/large kernels.
3. **Parallelization before VecPar helps medium kernels but hurts large ones**: On medium kernels, ParTile/ParThreads adds coarse-grained work distribution that helps. On large kernels, VecPar's implicit forall already maximizes parallelism.
4. **Tiling (scf.for) is almost always harmful for elementwise add**: Unlike matmul/conv which benefit from cache tiling, elementwise add is purely streaming — no data reuse to exploit.
5. **VecSeq is never the right terminal action for large kernels**: Its sequential loops waste all available parallelism.
