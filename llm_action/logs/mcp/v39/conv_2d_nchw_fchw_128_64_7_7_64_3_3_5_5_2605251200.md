**Key findings:**
- **Vec/ParVec cannot be applied directly to conv_2d_nchw_fchw** (postcondition fails). They can only be applied after Im2colLowering converts the conv to a linalg.generic.

- **Im2col self-blocks**: Cannot apply Im2col twice (precondition fails).
- **Tiling, LoopUnrolling, TilPar, DirPar compose freely** with all actions that aren't Vec/ParVec.
- After Im2col, Vec/ParVec become available but are terminal (matching matmul behavior).

**Key finding:** Im2col → ParVec[8,8,1,8] (M1) is the best schedule. The Im2col converts the conv to a batched matmul-like generic (dims 128x64x25 with 576-reduction), then ParVec vectorizes and parallelizes across all 4 dimensions. Adding TilPar before Im2col (M2) adds overhead without benefit since ParVec already handles parallelization.

## Phase 4: Local Tuning Summary

Best schedule: **Im2col → ParVec[8,8,1,8]** at **10.70ms** (13.7x vs MLIR base, 0.090x vs PyTorch)

Vector sizes [8,8,1,8] chosen because: batch=128÷8=16, F=64÷8=8 (divisible), spatial=25 (not divisible by 2/4/8 → use 1), reduction=576÷8=72 (divisible).
