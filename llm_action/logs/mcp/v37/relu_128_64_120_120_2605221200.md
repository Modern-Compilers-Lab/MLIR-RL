- **Parallelization dominates**: Memory-bound ReLU benefits almost exclusively from multi-threading.

## Key Insights
1. **Memory-bound kernels need parallelization, not tiling/vectorization**: ReLU on 900MB of f64 data is entirely memory-bandwidth-limited. Parallelization across 28 cores saturates memory bandwidth.
2. **ParaByThreads(28) beats PyTorch**: MLIR achieves 1.12x speedup over PyTorch JIT for this kernel, likely due to better thread distribution and lower overhead.
3. **Composition adds overhead, not speedup**: Every follow-up action after ParaByThreads either adds loop overhead (tiling, unrolling) or is a no-op (vectorization, interchange). The optimal schedule for this kernel is a single action.
4. **Vectorization is structurally terminal**: It replaces linalg.generic with vector ops, making subsequent linalg-targeted transforms ineffective. This is the only structural dependency in the v37 action space.
