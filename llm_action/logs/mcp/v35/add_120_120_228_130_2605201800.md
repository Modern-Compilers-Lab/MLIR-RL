## Summary

### Best Schedule
**PBT(28) → Tiling [0,8,4,0]**: 81.05 ms (7.83x over MLIR base, 1.60x over PyTorch)

### Key Insights
1. **Bandwidth-bound kernel**: 4D elementwise add on ~3.2 GB data (3 × 120×120×228×130 × 8B). Parallelization is the dominant optimization.
2. **PBT(28) is near-optimal**: full utilization of 28 cores on Broadwell E5-2680 v4, with minor improvement from cache tiling.
3. **Vectorization is permanently blocked after parallelization**: dynamic shapes from PBT/Par propagate through tiling, preventing the PBT→Tile→Vec HPC pattern.
4. **Vectorization alone is harmful**: overhead from vector operations without parallelism far outweighs any SIMD benefit for this streaming access pattern.
5. **LoopInterchange is harmful**: reordering dims for elementwise ops destroys row-major memory access order.
