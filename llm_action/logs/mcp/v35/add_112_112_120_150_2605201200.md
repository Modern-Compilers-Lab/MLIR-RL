| 4 | Unrolling(dim0,4) -> ParallelByThreads(28) | 92.51 | 3.65x | 0.74x |

**Key observations:**
- Tiling before ParallelByThreads is catastrophic: tiles reduce the linalg op to 4x4x4x150, then 28 threads split dim0=4 (24 threads idle). Overhead of spawning 28-thread forall 23520 times dominates.
- LoopInterchange[1,0,2,3] -> ParallelByThreads(28) is the BEST schedule found: 50.70ms (6.65x over base, 1.35x over PyTorch). The interchange swaps dims 0,1 so parallelization splits along dim1 instead of dim0, giving each thread a 112x4x120x150 slice. The different memory access pattern slightly improves cache behavior.
- Unrolling before ParallelByThreads creates 4 separate linalg.add ops of size 4x112x120x150, each parallelized with 28 threads on dim0=4. Same structural problem as Tiling, but only 4x overhead instead of 23520x, so less severe.
