## Summary

### Best Schedule
**Tiling[16,16,16]p=1 → Vectorization[4,4,4]p=0** at **0.96 ms**
- 339.6x speedup vs MLIR base (326.74ms)
- 0.47x vs PyTorch (0.45ms) — still ~2x slower than PyTorch JIT

### Action Sequence
1. Tiling {tile_sizes: [16,16,16], parallelize: 1} — creates 32K parallel 16×16 matmul tiles
2. Vectorization {vector_sizes: [4,4,4], parallelize: 0} — vectorizes each tile with 4×4 vector ops (TERMINAL)

### Key Insights
1. **Vectorization is terminal**: blocks ALL subsequent actions. Must be last in any schedule.
2. **Parallelism at tiling level**: `parallelize: 1` on Tiling is the primary speedup mechanism (130x alone)
3. **Vectorization adds ~2.7x** on top of parallel tiling (from 2.57ms to 0.96ms)
4. **Tile size sweet spot**: [16,16,16] balances task granularity vs overhead
5. **Vec sizes limited to [4,4,4]**: larger sizes fail postcondition regardless of tile size
6. **3+ step schedules**: no benefit over 2-step due to vectorization terminality
7. **Other actions (Interchange, Unrolling, Promotion)**: compose freely but provide no performance benefit when combined with the optimal Tile+Vec schedule

### Composability Rules (ACTION_DEPENDENCIES)
- Vectorization blocks: [Tiling, LoopInterchange, Vectorization, Unrolling, Parallelization, Promotion]
- All other actions: no blocks (compose freely)
