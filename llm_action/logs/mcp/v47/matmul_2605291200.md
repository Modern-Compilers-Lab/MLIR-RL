## Phase 2: Pairwise Compositions

### Composability Matrix (matmul_512_1024_512)

| Second \ First | Tiling | LoopInterchange | VecSeq | VecPar | ParTile | ParThread |
|----------------|--------|-----------------|--------|--------|---------|-----------|
| Tiling         | OK     | OK              | FAIL(post) | FAIL(post) | OK  | OK        |
| LoopInterchange| OK     | FAIL(pre)       | FAIL(post) | FAIL(post) | OK  | OK        |
| VecSeq         | OK     | OK              | FAIL(post) | FAIL(pre) | FAIL(pre) | FAIL(pre) |
| VecPar         | OK     | OK              | FAIL(pre) | FAIL(post) | OK  | OK        |
| ParTile        | OK     | OK              | FAIL(pre) | FAIL(post) | OK  | OK        |
| ParThread      | OK     | OK              | FAIL(post) | FAIL(post) | OK  | OK        |

### Key Structural Findings:
1. **VecSeq is terminal**: No action can successfully follow VecSeq (all fail post or pre). VecSeq vectorizes and consumes the linalg op, replacing it with vector operations. Tag moves to outer scf.for.
2. **VecPar is terminal**: All actions fail postcondition after VecPar. The inner matmul tiles are too small (4x4) and further ops don't produce valid postconditions.
3. **LoopInterchange→LoopInterchange FAIL(pre)**: LoopInterchange converts linalg.matmul to linalg.generic; the precondition of LoopInterchange requires linalg.matmul.
4. **VecSeq FAIL(pre) after ParTile/ParThread**: VecSeq can't handle matmul inside scf.forall (precondition fails).
5. **Tiling, ParTile, ParThread compose freely**: These can follow each other in any order.
6. **LoopInterchange composes as first action**: Can precede Tiling, VecSeq, VecPar, ParTile, ParThread (but NOT itself).

### Viable Schedule Prefixes (non-terminal):
- Tiling, LoopInterchange, ParTile, ParThread can be freely chained
- VecSeq can only follow: Tiling, LoopInterchange (not parallelization)
- VecPar can follow: Tiling, LoopInterchange, ParTile, ParThread
- Both vectorizations are terminal (must be last)
