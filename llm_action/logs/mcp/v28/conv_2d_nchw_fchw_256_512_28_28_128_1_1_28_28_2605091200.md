## Summary

**Best Schedule:** ParallelizationTiling[8,16] -> Tiling[0,0,4,4,8,0,0]
**Best Time:** 399.93 ms (48.0x vs MLIR base, 0.13x vs PyTorch)

### Key Findings:
1. **PT -> T beats Im2col -> PT -> T** for this kernel (399.93 vs 425.97ms)
2. K2 has 512 input channels vs K1's 128 - Im2col creates a larger col matrix (256x512x784) which increases memory pressure
3. Direct conv tiling with parallelization is more efficient when the reduction dimension (C_in=512) is large relative to the output channels (F=128)
4. Same composability patterns as K1 (both 1x1 convolutions)
5. Vectorization works (Pre=T, Post=T) but PT -> T remains faster

### Comparison with K1:
| Metric | K1 (C=128,F=512) | K2 (C=512,F=128) |
|--------|------------------|------------------|
| Best schedule | Im2col->PT->T | PT->T |
| Best time | 241.65ms | 399.93ms |
| Speedup | 75.5x | 48.0x |
| vs PyTorch | 0.17x | 0.13x |
| Im2col beneficial? | Yes | Marginal (only 6% slower without) |

The key difference: K1 benefits more from Im2col because the col matrix (256x128x784) is smaller than K2's (256x512x784). K2's larger reduction dim makes direct tiling competitive.
