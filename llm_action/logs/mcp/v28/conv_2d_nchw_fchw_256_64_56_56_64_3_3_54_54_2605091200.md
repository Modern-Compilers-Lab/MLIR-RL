## Summary

**Best Schedule:** ParallelizationTiling[8,8] -> Tiling[0,0,4,4,8,0,0]
**Best Time:** 1089.56 ms (vs PyTorch 185.14ms, 0.17x)

### Key Findings:
1. **Im2col is HARMFUL for 3x3 convolutions** (6300ms vs 1089ms without)
   - Creates tensor<256x576x2916xf64> intermediate (576 = 64*3*3, 2916 = 54*54)
   - Memory footprint: ~3.2GB for the col matrix alone (at f64)
   - 2916 mod 16 = 4, creating dynamic shapes with affine.min overhead
2. **PT -> T is the only viable schedule for 3x3 conv** (no im2col, no vectorization benefit)
3. **Vectorization works in principle** (Pre=T) but internally uses Im2col which is counterproductive for 3x3
4. **Same composability constraints** as 1x1 conv: Packing fails, Peeling fails, Promotion terminal
5. **Base MLIR times out (>60s)** showing extreme cost of unoptimized 3x3 conv on large spatial dims

### Kernel-Size-Dependent Strategy:
| Kernel Size | Best Strategy | Im2col? | Vectorization? |
|-------------|--------------|---------|---------------|
| 1x1 conv (K1, K2) | Im2col -> PT -> T or PT -> T | Beneficial for small C_in | Works via Im2col |
| 3x3 conv (K3) | PT -> T | Harmful (9x expansion) | Harmful (uses Im2col internally) |

### Why Im2col Hurts for 3x3:
- 1x1 conv Im2col: col_matrix = N x C x (OH*OW), expansion factor = 1x (no repeated data)
- 3x3 conv Im2col: col_matrix = N x (C*KH*KW) x (OH*OW), expansion factor = KH*KW = 9x
- The 9x expansion of the reduction dimension dominates memory bandwidth
- Additionally, 54*54=2916 is not evenly divisible by common tile sizes (16, 32), creating remainder handling overhead
