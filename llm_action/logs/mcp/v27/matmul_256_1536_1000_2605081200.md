## Key Findings

### Best Schedule
- Schedule: ParallelizationDirect[16,0,0] -> Tiling[4,4,4] -> Vectorization[4,4,4]
- Time: 6.83 ms
- Speedup: 80.5x vs MLIR base, 0.15x vs PyTorch

### Composability Issues Discovered
- **Vectorization is terminal**: All subsequent actions have Post=F because the linalg.matmul op is replaced with vector ops and the tag migrates to the outer scf.for loop
- **Unrolling is terminal**: All subsequent actions have Post=F because unrolling creates multiple tagged linalg op copies in the loop body
- **Dynamic dimension + Vec = execution failure**: Tiling with sizes that don't divide evenly creates dynamic-sized tiles; vectorization then generates masked vector ops that fail during lowering
- **All other 5 actions compose freely**: Tiling, Promotion, LoopInterchange, ParTiling, ParDirect all compose with each other (Pre=T, Post=T)

### Ordering Constraints
- Vectorization MUST be the last action in any schedule
- Unrolling MUST be the last action in any schedule
- Tiling tile sizes should evenly divide all dimensions when followed by vectorization
