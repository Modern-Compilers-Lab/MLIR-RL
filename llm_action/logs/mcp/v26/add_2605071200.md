**Key Findings for Composability:**
1. **Vectorization ALWAYS fails postcondition** on linalg.add - both standalone and after any prior action
2. **SplitReduction ALWAYS fails precondition** - linalg.add has no reduction dimensions
3. **Promotion ALWAYS fails precondition** - even after tiling, promotion fails on tensor-based code
4. **Packing** works but adds enormous overhead (padding + transpose + reverse), not beneficial for add
5. **Tiling after parallelization** adds sequential loops inside parallel tasks but no speedup
6. **Canonicalization** after parallelization simplifies IR but doesn't change performance meaningfully

| Kernel | Best Schedule | Time (ms) | Speedup vs Base | Speedup vs PyTorch |
|--------|--------------|-----------|-----------------|-------------------|

| K2 (112x15x15x15) | ThreadCount 4 | **0.233** | **1.47x** | **1.67x** |
| K3 (112x224x56x130) | TilingParallel [4,4,4] + Canon | **41.716** | **6.46x** | **1.34x** |
| K4 (120x120x228x130) | ThreadCount 28 | **82.441** | **7.72x** | **1.56x** |

### Key Insights

1. **Parallelization is the ONLY effective optimization** for elementwise add. All other single actions either fail, degrade performance, or are neutral.

2. **For small kernels (K2):** Fewer threads (ThreadCount 4) outperform fine-grained parallelism because the overhead of spawning many tasks exceeds the benefit.

3. **For medium kernels (K1):** TilingParallel [4,4,4] creates 28*28*4=3136 parallel tasks - optimal granularity.

4. **For large kernels (K3, K4):** More threads (ThreadCount 28) and fine-grained tiling-based parallelism both work well, achieving ~1.3-1.6x over PyTorch.

5. **Vectorization is broken** for linalg.add in v26 - postcondition always fails. This is a significant limitation since vectorization could provide further speedups.

6. **Packing is counterproductive** for elementwise operations - the data reorganization overhead (pad + expand + transpose + compute + transpose + collapse + extract) far exceeds any cache-locality benefit.

7. **Compositions provide minimal benefit** over the best single action. The parallelization alone captures most of the available performance.

8. **All kernels beat PyTorch** after optimization: K1 by 1.78x, K2 by 1.67x, K3 by 1.34x, K4 by 1.56x.
