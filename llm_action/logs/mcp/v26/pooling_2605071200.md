### Key Findings

1. **Parallelization is everything for pooling.** All 4 kernels achieve their best performance through parallelization (tiling_based_par or thread_count_par). Non-parallel transformations (tiling, interchange, unrolling) give at most 1.3x improvement.

2. **Tiling-based parallelization[4,4,4] is the universal best action** for pooling kernels. It tiles the N, C, and OH dimensions and runs them in parallel using scf.forall.

3. **Vectorization fundamentally does not work on pooling ops.** The postcondition fails in all cases (even after tiling). This is because pooling uses max reduction which the vectorizer cannot handle the same way as matmul/conv.

4. **Packing and split_reduction are also inapplicable** to pooling operations.

5. **Composition adds minimal value.** The best pairwise schedule (TP + Canon) is only marginally better than TP alone. Canonicalization cleans up redundant operations but doesn't change the computation structure.

6. **Order matters critically.** Parallelization -> Tiling works (tiling inside parallel region), but Tiling -> Parallelization typically targets wrong loop level and yields no benefit.

7. **Thread-count parallelization favors large batch dimension.** For K2 (largest spatial dims), TCP[28] slightly beats TP[4,4,4] because it distributes the batch dimension across all 28 threads effectively.

8. **All 4 kernels beat PyTorch** after parallelization, with K3 achieving the best speedup-to-PyTorch ratio of 4.04x.

### Recommended Default Schedule for Pooling

```
tiling_based_parallelization(tile_sizes=[4, 4, 4]) -> canonicalization({})
```

This schedule works universally across all pooling shapes and consistently delivers 8-27x speedup over unoptimized MLIR and 1.7-4.0x speedup over PyTorch.
