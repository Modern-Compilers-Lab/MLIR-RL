You are an expert MLIR optimization engineer.

Read CLAUDE_CODE_INSTRUCTIONS.md and MLIR_OPTIMIZATION_REFERENCE.md to understand the project and optimization techniques.

Your task: Autonomously optimize all matmul operations in this project to achieve <0.5x slowdown compared to PyTorch performance.

## Project Structure
- matmul_*.mlir: Input matrix multiplication operations (READ ONLY - do not modify)
- schedules/: Contains optimization schedules and lowering passes
- ./submit: Script to benchmark a schedule (usage: ./submit -<matmul_index> <schedule_name>)
- ./lower: Script to lower and analyze a schedule (usage: ./lower -<matmul_index> <schedule_name>)
- logs/: Benchmark results (READ ONLY - managed by SLURM)
- out/: Temporary lowering outputs (can delete files here)

## Your Workflow

For each matmul operation (matmul_1.mlir, matmul_2.mlir, etc.):

1. **Discover**: List all matmul_*.mlir files to see what needs optimization

2. **Analyze**: Examine existing schedules (schedules/baseline_*.mlir and .txt) to understand current approaches

3. **Iterate** (repeat until target achieved or convergence):
   
   a. **Create Schedule** (iteration N for matmul M):
      - Create schedules/claudeN_M.mlir with MLIR transform dialect optimizations
      - Create schedules/claudeN_M.txt with lowering pass sequence
      - Use insights from MLIR_OPTIMIZATION_REFERENCE.md and web search
   
   b. **Benchmark**:
      - Run: ./submit -M claudeN
      - Parse output to extract "Slowdown compared to PyTorch"
      - Goal: Get this under 0.5x
   
   c. **Analyze** (every 3-5 iterations for insights):
      - Clean: rm out/*
      - Lower: ./lower -M claudeN
      - Examine: cat out/output.ll.mlir and out/output.s
      - Look for vectorization, memory patterns, loop structure
   
   d. **Learn and Adapt**:
      - If slowdown improved: build on that approach
      - If slowdown worsened: try different strategy
      - Track what works in optimization_log.md

4. **Log Progress**: 
   - Maintain optimization_log.md with iteration results
   - Format: markdown table showing iteration, schedule name, slowdown, speedup, strategy

5. **Convergence**:
   - Stop when: slowdown < 0.5x (TARGET MET) OR no improvement for 5 iterations OR 50 iterations reached
   - Move to next matmul

6. **Final Report**:
   - Generate OPTIMIZATION_REPORT.md summarizing best schedules and performance for each matmul

## Naming Convention
- Schedules MUST be named: claude<N>_<M>.mlir and claude<N>_<M>.txt
- Where N is iteration number (1, 2, 3, ...) and M is matmul index
- Examples: claude1_1.mlir, claude1_1.txt, claude2_1.mlir, claude2_1.txt
